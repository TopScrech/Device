# Display and LiDAR catalogue audit

Checked 2026-10-23 for all 150 existing model definitions, including every hardware identifier and regulatory A-model in those definitions

## API and scope

- `Device.displays` contains every built-in pixel panel, including both iPhone Duo panels
- `nil` means an unknown model; an empty array means a known model without a conventional pixel display (Apple TV and HomePod)
- `Device.display` is the first catalogue panel, not a live active-screen query
- Native resolution is independent of the rendering buffer, orientation, display zoom and external monitors
- Aspect ratio is calculated exactly by reducing native width and height by their greatest common divisor; it can differ from DeviceKit's approximate 16:9, 19.5:9 or 4:5 labels
- Diagonal is in inches; iPad rectangular diagonals use Apple's footnotes where available
- Apple Watch has no published diagonal in this API; `estimatedDiagonal` uses the square root of the sum of squared pixel dimensions divided by PPI, and the app marks it as approximate
- Rounded corners describe the active pixel panel, not curved cover glass or a rounded enclosure
- LiDAR means a dedicated scanner, not TrueDepth, a proximity sensor or an Apple Watch depth gauge
- Added capabilities are also included in complete cellular/regional capability overrides
- Live brightness is not catalogue data; it is read on iOS and unavailable on the other app platforms

This covers the existing six-family catalogue, not an expansion into uncatalogued Mac or Vision Pro hardware

## Evidence

[DisplayEvidence.json](DisplayEvidence.json) records source references separately for **every specification of every model**, including derived aspect ratios, estimated diagonals, and explicit absence findings
Each field has at least two source references; model-to-screen mappings and shared screen constants are cross-referenced together
Apple technical specifications, Apple comparison tables and announcements were checked against the two pinned library catalogues, with firsthand hardware reviews and scanning-app compatibility filling gaps and resolving disagreements
The two libraries share some upstream data, and multiple Apple sources share a publisher; these are multiple sources, not a claim of independent laboratory measurement
For absent capabilities, evidence is the complete sensor/capability inventory rather than an unsuccessful keyword search
For screen shape, Apple display design descriptions supplement specification sheets and library capability sets
Source disagreements and precedence decisions are retained per model in the JSON, rather than counting a conflicting value as corroboration
The public libraries are research references only; neither is a dependency of this package
